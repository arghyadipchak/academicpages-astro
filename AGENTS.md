# AGENTS.md

Rules for AI coding assistants working on this repository. Features, setup and the AI prompt playbook are in [README.md](README.md)

`academicpages-astro` is an academic website template built with Astro 7, TypeScript and Tailwind CSS v4. Most copies of this repository are a person's own site, created with GitHub's "Use this template"

## Hard Rules

- **Footer credit**: Never remove, hide or comment out the credit in `src/components/Footer.astro` linking to `https://github.com/arghyadipchak/academicpages-astro` and the upstream academicpages project
- **No PRs to the template from personal sites**: When working on someone's site, never open a pull request against `arghyadipchak/academicpages-astro` or upstream `academicpages/academicpages.github.io`. Pull requests to the template are only for template-level fixes and improvements
- **Base path**: The site may be served under a sub-path, so route internal links and asset paths through `resolveUrl` in `src/utils/url.ts` instead of hardcoding root-relative URLs

## Where Things Live

- **Site identity, profile handles, theme and publication categories**: `src/data/siteConfig.ts` ([docs/CONFIG.md](docs/CONFIG.md))
- **Navigation**: `src/data/navigation.ts`
- **Content**: `src/content/<collection>/`, validated by the Zod schemas in `src/content.config.ts` ([docs/CONTENT.md](docs/CONTENT.md))
- **Markdown, KaTeX and Mermaid syntax**: [docs/MARKDOWN.md](docs/MARKDOWN.md)
- **CV**: `src/pages/cv.astro`

## Skills

Runbooks live in `.agents/skills/`. Read the matching one before starting these tasks:

- **`academicpages-onboarding/`**: Personalizing the site for its owner and purging demo content ([docs/ONBOARDING.md](docs/ONBOARDING.md))
- **`academicpages-add-publication/`**: Adding a paper from an arXiv ID, DOI, BibTeX entry or publisher link
- **`academicpages-content-operations/`**: Adding or editing any other content, the CV, profile or navigation
- **`academicpages-template-sync/`**: Upgrading to a newer template release ([docs/SYNC.md](docs/SYNC.md))

## Code Style

- **No trailing periods**: Never end single lines, list items or table cells with a period
- **Tailwind v4 syntax**: Write `border-(--global-border-color)`, not `border-[var(--global-border-color)]`
- **Semantic HTML**: Keep the `<header>`, `<main>`, `<nav>`, `<footer>`, `<aside>` and `<article>` landmarks
- **Strict types**: `astro check` must report zero errors

## Commands

Package manager is pnpm (Node >= 22.11)

```bash
pnpm dev                 # dev server on :4321
pnpm test                # Playwright e2e (Desktop Chrome + Mobile Chrome projects)
pnpm test tests/core.spec.ts                      # one spec file
pnpm test -g "search" --project="Desktop Chrome"  # tests matching a title, one project
pnpm generate:favicons   # regenerate favicons from public/favicon.svg
```

Playwright starts its own server: `pnpm dev` locally (reuses one already running), `pnpm preview` under `CI=1`, so run `pnpm build` first when testing CI-style. `TEST_PORT` overrides the port. `api.spec.ts` runs only on the desktop project

## Architecture Notes

- **Base path**: `ASTRO_URL` (set by CI from GitHub Pages) overrides `siteConfig.url`; its origin becomes `site` and its pathname becomes `base` in `astro.config.ts`. Playwright config and `tests/fixtures/test-utils.ts` (`toUrl`) derive the same base. `resolveHtmlUrls` applies the same rule to rendered HTML strings
- **Routing**: the `blog` collection is served under `/posts/`, other collections under their own name. `[...slug].astro` pages use `buildCollectionPaths`, which emits a route for both the filename slug and any frontmatter `permalink`; link to entries with the `get*Url` helpers
- **Schemas**: `src/content.config.ts` holds the Zod schemas; publication `category` is an enum built from the keys of `siteConfig.publicationCategories` (first key is the default)
- **Markdown**: body content goes through `remark-math`/`rehype-katex` plus the custom rehype plugins in `src/plugins/`; frontmatter strings (titles, citations) are rendered separately via `marked` + KaTeX in `src/utils/marked.ts`
- **Generated endpoints**: `src/pages/*.ts` produce `rss.xml`, `feed.xml`, `llms.txt`, `robots.txt`, `site.webmanifest`, `/api/search.json` (feeds the Cmd/Ctrl+K search modal) and per-page OG images under `/og/`. New content types or fields usually need wiring into these too
- **Themes**: presets live in `src/data/themes.ts`, design tokens in `src/styles/global.css`
